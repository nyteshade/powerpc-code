# ppcode

You are working on ppcode itself: a terminal coding assistant written in C++23,
running natively on a PowerPC Power Mac G5 under Mac OS X Server 10.5.8.

## Building

Build with `gmake`, never `/usr/bin/make`. Use the `build` tool rather than
running the compiler through `bash` — it returns structured diagnostics instead
of several hundred lines of log.

Compile time is around 15 seconds per translation unit that includes
`third_party/nlohmann/json.hpp`, so a full rebuild is a couple of minutes. Build
with `-j2`; the machine has two cores.

Run `./build/ppcode --selftest` after any change. It is fast, offline, and covers
the parsers and tool behaviour. Add a check there for anything you fix.

## Hard rules for this codebase

- **No C++ iostreams.** Not `<iostream>`, `<fstream>`, `<sstream>` or
  `<iomanip>`. Linking libcurl pulls in CoreServices and therefore Leopard's own
  libstdc++ alongside gcc15's, and Darwin coalesces weak symbols process-wide, so
  any iostream use frees memory across runtimes and floods stderr with
  `Non-aligned pointer being freed`. Use stdio and the `read_file_text` /
  `write_file_text` helpers. `gmake lint` enforces this and will fail the build.

- **Do not name a local `hline`, `vline`, `border`, `clear` or `move` in any file
  that includes `ncurses.h`.** Those are macros that inject `stdscr` as a first
  argument, and the resulting error points at something unrelated.

- **Measure display width with `utf8::`, never `std::string::size()`,** anywhere
  text reaches the screen. Byte-based wrapping splits multi-byte sequences and
  paints garbage.

- **Watch for `size_t` underflow** when computing padding. `field - width` where
  width exceeds field produces a multi-gigabyte string; guard the subtraction.

## Conventions

- The `Agent` class owns the model/tool loop and is front-end agnostic. New
  features should be wired through `Agent::Events` so the TUI and the headless
  runner both get them, rather than implemented in one front end.
- Tools live in a `ToolRegistry`. Read-only tools bypass the approval gate;
  anything that mutates or reaches the network must be `ToolKind::Mutate` or
  `ToolKind::Execute` and should supply a `preview` so the prompt is meaningful.
- Comments explain *why*, not *what*. Prefer a sentence about the constraint that
  forced a decision over a restatement of the code.
- British spelling in prose is fine; keep identifiers ASCII.
